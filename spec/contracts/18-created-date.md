# §20 Todos: show the creation date

Tier: full

- [ ] Lead approves spec (plan gate of B4.1; D-22, D-24)

## Intent

A person looking at the list sees, on every item's row, the day the item was added, so an old item is told from a new
one without opening anything. The day is the same on every screen, in every time zone and after every reload, it never
changes while the item is ticked, renamed or given a due date, and it adds no control and no new line of text to the
row that a person or a test reads as the item's own words.

## Requirements (EARS)

| ID       | Pattern      | Requirement                                                                                                                                                                                                                                                                                                                                                    |
| -------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-20.1 | Ubiquitous   | THE SYSTEM SHALL write a todo's creation day as `YYYY-MM-DD` (four-digit year, month and day padded to 2) of the todo's `createdAt` instant (§5) in UTC; the server's time zone, the browser's time zone and the locale are never used, and no time of day is written.                                                                                         |
| REQ-20.2 | Ubiquitous   | THE SYSTEM SHALL word the creation day as `Created <day>` (the word `Created`, one space, the day of REQ-20.1), in the same plain `YYYY-MM-DD` style as `Due <date>` (§15).                                                                                                                                                                                    |
| REQ-20.3 | Ubiquitous   | THE SYSTEM SHALL render in every listed todo's row, in view mode and in edit mode, exactly one `<time>` element that has no child node, a `datetime` attribute equal to the day of REQ-20.1 and a `data-created` attribute equal to the wording of REQ-20.2, so that the row's text content and its accessible controls are exactly what they were without it. |
| REQ-20.4 | Ubiquitous   | THE SYSTEM SHALL display the wording of REQ-20.2 in the row as generated content of that `<time>` element, taken from its `data-created` attribute (CSS `content: attr(data-created)`), so that the date is visible on screen (the element's box is at least 1 px wide and 1 px high) while it is not part of the row's text content.                          |
| REQ-20.5 | Ubiquitous   | THE SYSTEM SHALL render the same `<time>` element, with the same attribute values, on the server and in the browser's first render, from `createdAt` alone, with no clock read, no state and no effect, so that no hydration mismatch occurs and the value does not depend on when or where the page is rendered.                                              |
| REQ-20.6 | Event-driven | WHEN the row renders again because its todo was ticked or unticked (§5), its title was saved (§6), its due date was set or cleared (§15), or the page was reloaded THE SYSTEM SHALL show the same wording for the same `createdAt`; THE SYSTEM SHALL never write `createdAt`, so the list order of §5 is unchanged.                                            |
| REQ-20.7 | Ubiquitous   | THE SYSTEM SHALL add no control, no `role`, no `aria-label` and no checkbox to the row: the completion checkbox stays the first checkbox of the `<li>` (§17 reads it), and the row keeps exactly one button named "Edit title" (view mode), one named "Edit due date" and one named "Delete todo".                                                             |

`createdAt` is a valid `Date` read from the database (§5, §3); an invalid `Date` is not handled. UTC is chosen because
the server render and the browser's first render must write the same attribute without reading a clock (REQ-20.5): a
browser-local day would differ from the server's for a person outside UTC. The day a person sees can therefore be one
day off their own calendar for an item added within a few hours of local midnight; §17's "today" is browser-local and is
a separate rule that this section does not touch. The date is generated content and not text so that the §5, §6, §10,
§12, §13, §14 and §19 criteria, which read each `<li>`'s whole text as the title, hold; a consequence is that browsers do
not let a person select it, find it with page search or copy it.

## Function contracts

```ts
// src/lib/todo-created.ts (§20): pure; no Prisma, no server-only, so a client component may import it
export const CREATED_PREFIX: 'Created ';
export function createdDayOf(createdAt: Date): string; // `${String(createdAt.getUTCFullYear()).padStart(4, '0')}-${MM}-${DD}` from getUTCMonth() + 1 and getUTCDate(), each padded to 2; never local time, never Intl
export function createdLabel(createdAt: Date): string; // `${CREATED_PREFIX}${createdDayOf(createdAt)}`
// src/components/todo-item.tsx (§7, extended; no new component, props unchanged)
export function TodoItem({ todo }: { readonly todo: Todo }): ReactNode; // as §6, §10, §15, §19, plus one empty <time dateTime={createdDayOf(todo.createdAt)} data-created={createdLabel(todo.createdAt)}> placed after <TodoDueDate> and before the §10 alert, rendered in view and edit mode, with the CSS class that sets `content: attr(data-created)` on its ::after; no state, no effect, no new import other than src/lib/todo-created.ts
```

No file other than `src/lib/todo-created.ts` and `src/components/todo-item.tsx` changes in `src/`: `src/lib/todos.ts`
(`Todo.createdAt` and its select already exist), the actions, the page, `src/components/todo-due-date.tsx` and the
logger keep their contracts. Test note: no existing test file changes, because `TodoItem` imports no new action
module and every existing `todo` factory already carries a valid `createdAt`; the hydration criterion lives in a new
file, `src/components/todo-item-created.test.tsx`, which mocks `@/actions/todos` and `@/actions/delete-todo` at the
boundary.

## Out of scope

A time of day, a relative wording ("3 days ago"), a locale- or zone-formatted date, a browser-local creation day, a
tooltip, a sort or filter or search by creation date, a "last edited" date, showing the date in the `<li>`'s text
content (see the paragraph under the requirements), a toggle to hide the date, a change to the stored `createdAt`, an
invalid `Date`, and any change to the page layout outside the row (§7).
