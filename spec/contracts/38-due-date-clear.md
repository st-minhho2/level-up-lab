# §40 Todos: a "Clear due date" button removes the due date in one step

Tier: full

- [ ] Lead approves spec

## Intent

A person who no longer wants a day on an item opens its due-date editor and removes the day with one press, instead
of emptying the date field by hand and then saving. The press saves at once: the row afterwards looks as it did before
it had a due date, and a failed save is reported where a failed "Update due date" is reported.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-40.1 | State-driven      | WHILE a row is in due-date edit mode (§15 REQ-15.6), with or without a stored due date, THE SYSTEM SHALL show in the edit form, in this order, the label "Due date", the date field, the button "Today" (§37), one button named exactly "Clear due date" with `type="button"` and the visible text `Clear due date` (no `aria-label`, no `title`), and the button "Update due date". The name is never exactly "Due date" and never `Clear`.                  |
| REQ-40.2 | Event-driven      | WHEN a person activates "Clear due date" THE SYSTEM SHALL call `setTodoDueDateAction(todoId, '')` exactly once, whatever the date field holds (a typed, filled or stored value is not sent), and SHALL NOT submit the form a second time.                                                                                                                                                                                                                     |
| REQ-40.3 | Event-driven      | WHEN that call returns `ok` THE SYSTEM SHALL leave edit mode and remove the row's message, as a successful "Update due date" does (§15 REQ-15.6, REQ-15.11); the stored due date is then none and the row shows no due-date text (§15 REQ-15.3, REQ-15.9), no `Overdue` marker (§17) and no `Due today` marker (§31).                                                                                                                                         |
| REQ-40.4 | Unwanted behavior | IF that call returns a failure THEN THE SYSTEM SHALL stay in edit mode with the date field holding what it held before the activation, and show in the wrapper the one message `fieldErrors.dueDate?.[0] ?? fieldErrors.id?.[0] ?? fieldErrors.form?.[0]` as "Update due date" does (§15 REQ-15.7, REQ-15.10; for a failed save the §10 message `Could not save, try again`); the next success removes it (§15 REQ-15.11).                                    |
| REQ-40.5 | State-driven      | WHILE a save of that todo's due date is in flight, started by any control of the form, THE SYSTEM SHALL disable "Clear due date" as it disables "Today" and "Update due date" (§15, §37 REQ-37.5), and ignore Escape on it (§28 REQ-28.5).                                                                                                                                                                                                                    |
| REQ-40.6 | Event-driven      | WHEN Escape (as defined in §28 REQ-28.1) is pressed while "Clear due date" has focus THE SYSTEM SHALL do what §37 REQ-37.4 specifies for "Today": leave edit mode, show the stored due date, cancel the key's default action, make no save, discard the draft and remove the row's message. A key other than Escape, or Escape with Ctrl, Meta, Alt or Shift, keeps the browser's behavior for a button (§28 REQ-28.6): no `preventDefault`, edit mode stays. |
| REQ-40.7 | Ubiquitous        | THE SYSTEM SHALL show no "Clear due date" button outside edit mode, so the row's markup in view mode is the one of §15, §17, §31 and §37, and SHALL change no server, Server Action, Zod schema, Prisma model, query or `src/lib` function: the button sends the value that §15 REQ-15.3 already accepts.                                                                                                                                                     |

Edits to other sections that this one makes (D-37), written against §37's text:

- §15 REQ-15.6 and the §15 contract list "Clear due date" in the ordered list of the form's buttons, between "Today"
  and "Update due date".
- §28 REQ-28.7 limits §28's own change (Escape in the field); it does not apply to §40. §28's Out of scope "a
  "Cancel" button" does not apply: "Clear due date" saves an empty date, it does not cancel the edit. §28's Escape
  reactions stay as they are (none on `document.body`, on "Update due date", in a title field or any other box);
  §40 adds one: on "Clear due date" (REQ-40.6), as §37 added one on "Today".
- The "a new control" lines of §17's (`15-overdue.md`) and §31's (`29-due-today.md`) Out of scope limit those
  sections' own markers; they do not apply to §40's button. REQ-17.8 and REQ-31.7 describe view mode and do not apply
  to edit mode.
- §37 REQ-37.1, AC-37.1 and REQ-37.3 are edited under D-38: REQ-37.1 lists "Clear due date" between "Today" and
  "Update due date"; AC-37.1 reads "exactly 5" children in that order; REQ-37.3 allows the date to be cleared by
  "Clear due date". B7.3's existing AC-37.1 test (merged from PR #301 by the time this lands) is rewritten to 5
  children in B7.6's red commit.
- The lines of §17, §19, §20, §23, §28 and §31 that say a file or a contract "keeps" or "stays as it is" describe
  that section's own change; they do not forbid this section's change to `src/components/todo-due-date.tsx`.

## Function contracts

```ts
// src/components/todo-due-date.tsx (§15, §17, §28, §31, §37, extended; no new component, props unchanged)
export function TodoDueDate({
  todoId,
  dueDate,
}: {
  readonly todoId: string;
  readonly dueDate: string | undefined;
}): ReactNode; // as §37, plus: in edit mode the <form> holds, in order, the visually hidden <label> "Due date", the <input type="date">, "Today" (§37), <button type="button" onClick> with the visible text `Clear due date` (no aria-label, no title; disabled while pending), and the submit button "Update due date"; the click calls setTodoDueDateAction(todoId, '') in the same transition and with the same result handling as onSave (ok → leave edit mode and clear the message; failure → keep edit mode and the draft, show fieldErrors.dueDate?.[0] ?? fieldErrors.id?.[0] ?? fieldErrors.form?.[0]); its onKeyDown is the §28 handler of the field (Escape, no Ctrl/Meta/Alt/Shift, not pending → preventDefault, leave edit mode, draft ← dueDate ?? '', clear the message)
```

The only file of `src/` this section changes is `src/components/todo-due-date.tsx`. No new export, Server Action,
Zod schema, Prisma model, query, environment variable, prop or lib function. `src/app/page.tsx`,
`src/actions/todos.ts`, `src/components/todo-item.tsx` and `src/lib/*` keep their contracts.

## Out of scope

A confirmation before clearing, undo, hiding the button while no date is stored, a keyboard shortcut for clearing,
restoring focus to "Edit due date" after the clear or after Escape, announcing the removal to assistive technology,
a "Clear" button outside edit mode, clearing from the list or in bulk, a "Cancel" button, any change to the server,
the action, the schema or `src/lib`.
