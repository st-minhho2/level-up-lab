# §45 Todos: opening the due-date editor puts focus in the date field

Tier: full

- [ ] Lead approves spec

## Intent

A person who opens an item's due-date editor wants to change the day. Today the "Edit due date" button disappears
when the editor opens, so focus falls to the page and one more click or Tab comes before the first useful key. After
this section the editor opens ready: the cursor is in the date field, which shows the current date, so the next key
edits it. Nothing else about the editor changes.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| REQ-45.1 | Event-driven      | WHEN a person activates the "Edit due date" button of a row (§15 REQ-15.6) THE SYSTEM SHALL, with the date field labelled "Due date" shown, make that field `document.activeElement`; the field holds the todo's current due date, or is empty when there is none (§15 REQ-15.6).                                                                                                                                  |
| REQ-45.2 | Event-driven      | WHEN a row enters edit mode again after leaving it, by Escape (§28 REQ-28.1), by a successful save or by a successful "Clear due date" (§15 REQ-15.6, §40 REQ-40.3), THE SYSTEM SHALL do as REQ-45.1 with the due date then stored, so the focus never depends on an earlier edit.                                                                                                                                 |
| REQ-45.3 | Unwanted behavior | IF a row that is already in edit mode stays in it after a rejected save (§15 REQ-15.7) or a failed save (§15 REQ-15.10), or re-renders for any other reason (a new `dueDate` prop, a save pending or settled, a message shown or removed, a key typed, "Today" activated), THEN THE SYSTEM SHALL NOT focus a control: whatever had focus keeps it, and the field keeps its draft.                                  |
| REQ-45.4 | Ubiquitous        | THE SYSTEM SHALL move focus into the date field only on the switch from view mode into edit mode (REQ-45.1, REQ-45.2): a row that renders in view mode, a row that leaves edit mode by a save or a clear (§15, §40; a row that leaves it by Escape gets the focus §51 says, on the button "Edit due date", never on the field), and a row other than the one whose "Edit due date" was activated receive no focus. |
| REQ-45.5 | Ubiquitous        | THE SYSTEM SHALL change nothing but focus: the field's value, label, `id` and attributes, the order and names of the form's controls, the row's text content, the Escape, Enter, "Today" and "Clear due date" behavior of §15, §28, §37 and §40, and the request count (none on activation) are those of those sections; the field's text is not selected by the focus, as §41's selection is for the title only.  |

## Function contracts

```ts
// src/components/todo-due-date.tsx (§15, §17, §28, §31, §37, §40, extended; no new component, props unchanged)
export function TodoDueDate({
  todoId,
  dueDate,
}: {
  readonly todoId: string;
  readonly dueDate: string | undefined;
}): ReactNode; // as §40, plus: when the component changes from view mode into edit mode (the click of "Edit due date", onEdit), after the date <input> is in the document it receives focus(), once for that switch; a re-render in edit mode, a rejected or failed save, a changed dueDate prop, "Today", "Clear due date" and the exit from edit mode by a save or a clear do not call focus() or select() or set a selection range (an exit by Escape focuses the "Edit due date" button, §51)
```

The only file of `src/` this section changes is `src/components/todo-due-date.tsx`. No new export, Server Action, Zod
schema, Prisma model, query, environment variable, prop or lib function. `src/app/page.tsx`,
`src/actions/todos.ts`, `src/components/todo-item.tsx` and `src/lib/*` keep their contracts.

How the criteria observe it: jsdom supports `focus()` and `document.activeElement` on an `input`, so AC-45.1 to AC-45.6
are component tests with Testing Library (a spy on `HTMLInputElement.prototype.focus` counts the calls in AC-45.5);
AC-45.7 is a Playwright test that reads `document.activeElement` with `page.evaluate`.

## Out of scope

Restoring focus to the "Edit due date" button after a save (§28, §37, §40), moving focus anywhere on leaving edit mode
other than by Escape (§51) or after the click of "Today" or "Clear due date", selecting the date field's text or one of its segments, opening the
browser's date picker, focusing the field of a row other than the one activated, focusing the title field (§6, §41),
scrolling the row into view, a focus style of our own, entering edit mode by a key, announcing the focus to assistive
technology.
