# §21 Todos: clear the search

Tier: full

- [x] Lead approves spec (lead, 2026-11-01, plan gate of B4.2; D-24)

## Intent

A person who searched the list (§16) gets back to the full list in one step, without selecting the text in the search
box and deleting it. The step is a link that is there only while a search is in effect. Following it leaves the
All / Active / Completed view already chosen as it is, and shows every item that view allows. Nothing stored changes.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                |
| -------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| REQ-21.1 | State-driven      | WHILE a search is in effect (the query of §16 is not empty once trimmed, REQ-16.3) THE SYSTEM SHALL show on `/`, inside the search form of §16 and after its "Search" button, exactly one link whose text and accessible name are `Clear search`, in every state (an empty list included). |
| REQ-21.2 | Unwanted behavior | IF no search is in effect (the `q` parameter is absent, empty, only whitespace or repeated, REQ-16.4) THEN THE SYSTEM SHALL show no "Clear search" link.                                                                                                                                   |
| REQ-21.3 | Event-driven      | WHEN a person follows the "Clear search" link THE SYSTEM SHALL open `/` when the selected filter is All and `/?filter=<filter>` otherwise (`/?filter=active`, `/?filter=completed`, the addresses of §12 REQ-12.6), and the address SHALL carry no `q`.                                    |
| REQ-21.4 | Event-driven      | WHEN the page opened by the link is shown THE SYSTEM SHALL list every todo the selected filter allows (REQ-16.4), in the order of §5, show the search box empty, show no "Clear search" link, and, if that list is empty, show the empty text of §12, not "No todos match your search".    |
| REQ-21.5 | Ubiquitous        | THE SYSTEM SHALL make the control an anchor with an `href` that navigates with the GET method, so that it works with JavaScript disabled, and SHALL NOT make it a button or a list item.                                                                                                   |
| REQ-21.6 | Ubiquitous        | THE SYSTEM SHALL NOT, by showing or following the link, change any stored todo, the order of §5, the remaining count (§13), the enabled state of "Clear completed" (§12) and of "Mark all complete" (§14), or the label, box, "Search" button and hidden `filter` input of §16.            |

"A search is in effect" has one definition, the one §16 applies: the query read from `q` (`parseSearchQuery`, §16) is
non-empty. A query longer than 200 characters is in effect (it matches no todo, REQ-16.5), so the link is shown and is
the way out of an empty result. Following a filter link (§12) already drops `q` (REQ-16.7) and so already hides the
"Clear search" link; the new link differs only in keeping the selected filter. The text `Clear search` is the only
visible text added, and it is not a "Search" button: a button named "Search" stays unique (REQ-16.1).

## Function contracts

```ts
// src/lib/clear-search.ts (§21; pure: no Prisma, no server-only; importable from a Server Component)
import type { TodoFilter } from '@/lib/todo-filter'; // §12
export const CLEAR_SEARCH_LABEL: string; // 'Clear search': the link's text and accessible name, no aria-label
export function isSearchInEffect(query: string): boolean; // query.trim() !== '' (the same trim as parseSearchQuery, §16); never throws
export function clearSearchHref(filter: TodoFilter): string; // 'all' → '/'; 'active' → '/?filter=active'; 'completed' → '/?filter=completed'; never a q
// src/components/todo-search-form.tsx (§16, extended by §21; still no 'use client': no state or events)
export function TodoSearchForm({ filter, query }: { readonly filter: TodoFilter; readonly query: string }): ReactNode; // unchanged signature and §16 markup; inside the <form>, after the <button type="submit">Search</button>, only when isSearchInEffect(query): <Link href={clearSearchHref(filter)}>{CLEAR_SEARCH_LABEL}</Link> (next/link, rendered as an <a>, as the links of §12)
```

The input keeps the `key` of §16 (filter and query), so when the link is followed the query changes to empty, the key
changes, and the box remounts empty (REQ-21.4). `src/app/page.tsx` does not change: it already passes the parsed
`filter` and `query` to `TodoSearchForm`. `src/lib/todo-search.ts`, `src/lib/todo-filter.ts`,
`src/components/todo-filter-nav.tsx`, `src/components/todo-item.tsx`, `src/components/remaining-count.tsx`,
`src/lib/todo-count.ts`, `src/lib/todos.ts` and `src/actions/todos.ts` do not change; no action takes part.

Test note for `src/components/todo-search-form.test.tsx` (an existing file): the §21 cases are added to it; its §16
tests are not changed, because none of them asserts that a link is absent.

## Out of scope

A "clear" control inside the search box (the `x` of a browser's `type="search"` input), a button or a keyboard shortcut
for clearing, clearing the filter as well (the filter links of §12 do that), keeping the search when a filter link is
followed (§16), a link shown when no search is in effect, an animation or a focus move after following the link,
client-side navigation by script, a count of the matches cleared, remembering the cleared search, a change to the
remaining count, "Clear completed" or "Mark all complete" (§12, §13, §14), any change to the page layout outside the
search form (§7).
