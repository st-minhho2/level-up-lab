# §16 Todos: search by title

Tier: full

- [x] Lead approves spec (lead, 2026-10-31, plan gate of B2.5; D-21)

## Intent

A person with a long list types a few letters of an item's title and sees only the items that contain them, together
with the All / Active / Completed view already chosen. The search is part of the page address, so a reload or a shared
link shows the same view. Searching changes what is shown, never what is stored, in which order, or how many items
are counted as still open.

## Requirements (EARS)

| ID        | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                             |
| --------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-16.1  | Ubiquitous        | THE SYSTEM SHALL show on `/`, in every state (empty list included), a search form (landmark `search`) holding a search box labelled "Search todos", limited to 200 characters, and a submit button named "Search"; none of them is a list item.                                                                                         |
| REQ-16.2  | Ubiquitous        | THE SYSTEM SHALL carry the search in the `q` query parameter, sent by submitting the form with the GET method to `/`, and SHALL show the current query (trimmed) in the search box, so that a full page reload shows the same view.                                                                                                     |
| REQ-16.3  | State-driven      | WHILE a search is active THE SYSTEM SHALL list only the todos whose title contains the trimmed query as a substring, ignoring letter case, and SHALL keep every other rule of the list.                                                                                                                                                 |
| REQ-16.4  | Unwanted behavior | IF the `q` query parameter is absent, empty, only whitespace, or repeated, THEN THE SYSTEM SHALL treat it as no search (every todo that the selected filter allows is listed) and report no error.                                                                                                                                      |
| REQ-16.5  | Ubiquitous        | THE SYSTEM SHALL compare the query as plain text: every character stands for itself (no wildcard, no pattern, no word splitting), accents are not folded, and a query longer than 200 characters (UTF-16 code units, as §5 counts titles) matches no todo.                                                                              |
| REQ-16.6  | State-driven      | WHILE a search is active and a filter other than All is selected (§12) THE SYSTEM SHALL list only the todos that satisfy both, and submitting the search form SHALL keep the selected filter in the address.                                                                                                                            |
| REQ-16.7  | Event-driven      | WHEN a person follows a filter link (§12) THE SYSTEM SHALL show that filter without a search, because the link addresses of §12 carry no `q`.                                                                                                                                                                                           |
| REQ-16.8  | State-driven      | WHILE the list shown is empty, at least one todo is stored and a search is active THE SYSTEM SHALL show "No todos match your search", under every filter; when no todo is stored the text is "No todos yet" (§12 REQ-12.8).                                                                                                             |
| REQ-16.9  | Ubiquitous        | THE SYSTEM SHALL keep the todos shown in the order of §5 (creation time, newest first), SHALL NOT change any stored todo by searching, and SHALL derive the remaining count (§13 REQ-13.5), the enabled state of "Clear completed" (§12 REQ-12.10) and of "Mark all complete" (§14) from every stored todo, whether or not it is shown. |
| REQ-16.10 | Event-driven      | WHEN a todo is created, toggled, edited, cleared or marked complete (§5, §6, §9, §14) while a search is active THE SYSTEM SHALL keep the search and apply it to the stored todos, so a todo whose title no longer matches leaves the list.                                                                                              |

The search is a view over the list `listTodos()` returns (§5), read once per render and filtered in memory, after the
§12 filter (both only keep or drop todos, so the order of the two steps does not change the result). Titles,
duplicates, completion and order are those of §5. "Mark all complete" (§14) marks every stored open todo, including
those a search hides; the filter of §12 has the same reach. The 200-character limit is the title limit of §5
(`TITLE_MAX_LENGTH`).

## Function contracts

```ts
// src/lib/todo-search.ts (pure: no Prisma, no server-only; importable from a client component)
export const SEARCH_QUERY_MAX_LENGTH: number; // 200, the value of TITLE_MAX_LENGTH from '@/lib/todo-schema' (§5); one definition
export function parseSearchQuery(value: string | string[] | undefined): string; // a string is trimmed; undefined, an array (repeated parameter) and '' give ''; never truncates, never throws
export function searchTodos<T extends { readonly title: string }>(todos: readonly T[], query: string): T[]; // trims query; a trimmed query whose length exceeds SEARCH_QUERY_MAX_LENGTH (UTF-16 code units, as §5 counts titles) returns [] before any comparison; '' keeps all; else title.toLowerCase().includes(query.toLowerCase()); keeps input order; returns a new array; never mutates
export function searchEmptyMessage(filter: TodoFilter, totalCount: number, query: string): string; // for an empty list shown: totalCount === 0 → 'No todos yet'; trimmed query !== '' → 'No todos match your search'; else emptyListMessage(filter, totalCount) (§12)
// src/components/todo-search-form.tsx (no 'use client': a native GET form, no state or events)
export function TodoSearchForm({ filter, query }: { readonly filter: TodoFilter; readonly query: string }): ReactNode; // <form role="search" method="get" action="/"> with <label htmlFor> "Search todos" (sr-only), <input type="search" name="q" maxLength={200} defaultValue={query}>, <button type="submit">Search</button>, and <input type="hidden" name="filter" value={filter}> only when filter !== 'all'
// src/app/page.tsx: HomePage({ searchParams }: { searchParams: Promise<{ filter?: string | string[]; q?: string | string[] }> }) reads
// parseSearchQuery((await searchParams).q); the list is searchTodos(filterTodos(todos, filter), query); renders <TodoSearchForm filter={filter} query={query} />
// outside the list in both states (position is the mounting card's choice); the empty <p> text is searchEmptyMessage(filter, todos.length, query);
// <RemainingCount>, <ClearCompletedButton disabled> and <CompleteAllButton disabled> keep deriving from the unfiltered, unsearched todos
```

`src/lib/todos.ts`, `src/lib/todo-schema.ts` and `src/actions/todos.ts` do not change: `listTodos()` still returns every
todo, and no action takes a query. `src/lib/todo-filter.ts` and `src/components/todo-filter-nav.tsx` do not change:
the filter links still point to `/`, `/?filter=active`, `/?filter=completed` (§12 REQ-12.6), so following one drops `q`.

## Out of scope

Highlighting the matched text, search as you type or any debounce, searching anything but the title (a due date,
section 15, is not searched), several words, fuzzy matching, regular expressions, wildcards, accent folding,
locale-aware case folding, a search in the database query, client-side navigation for the form (`next/form`), a
"clear search" link, keeping the search when a filter link is followed (that needs a change to §12 REQ-12.6), counts
of matches, limiting the remaining count, "Clear completed" or "Mark all complete" to the todos shown, remembering the
search outside the address (cookie, local storage), keyboard shortcuts, any ordering other than creation time newest
first (§1).
