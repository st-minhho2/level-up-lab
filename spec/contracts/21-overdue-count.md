# §23 Todos: show how many open todos are overdue

Tier: full

- [ ] Lead approves spec

## Intent

A person who keeps due days (§15) sees at the top of the page how many open todos have already missed theirs, without
reading every row for the `Overdue` text of §17. The number is silent when nothing is late, follows every change to the
list without a reload, and is not changed by a filter or a search.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                               |
| -------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-23.1 | Ubiquitous        | THE SYSTEM SHALL show on `/` the number N of stored todos that are overdue by the rule of §17 (`isOverdue`: not completed, due date strictly before today), written `N overdue`, where today is the browser's local calendar day (§17 REQ-17.1).                                                          |
| REQ-23.2 | State-driven      | WHILE N is 0 THE SYSTEM SHALL show no text for it: no `0 overdue`, no empty placeholder text.                                                                                                                                                                                                             |
| REQ-23.3 | Unwanted behavior | IF a filter (§12) or a search (§16) hides some or all of the stored todos THEN THE SYSTEM SHALL still count every stored todo (§13 REQ-13.5), so that neither shows, removes or changes the number.                                                                                                       |
| REQ-23.4 | Event-driven      | WHEN a todo is created (§5), toggled (§5), given, changed or cleared of a due date (§15), completed in bulk (§14), cleared (§9) or deleted (§19) THE SYSTEM SHALL show the new N in the same page without a full reload, and a full page reload SHALL show the same N.                                    |
| REQ-23.5 | Ubiquitous        | THE SYSTEM SHALL render the same markup on the server and in the browser's first render, with no overdue count in it, and add the count only after hydration, so that no hydration mismatch occurs and the server's output does not depend on the date.                                                   |
| REQ-23.6 | State-driven      | WHILE the page stays open across the browser's local midnight THE SYSTEM SHALL keep using the day read when the count first rendered in the browser; a reload evaluates the new day, a timer never does (as §17 REQ-17.7).                                                                                |
| REQ-23.7 | Ubiquitous        | THE SYSTEM SHALL show the count as plain text in one element outside the list, after the §13 paragraph, that is not a `<p>`, `<li>`, `<button>`, `<a>` and has no role and no `aria-label`, so that §13's "exactly one paragraph", §22's "All done", and the `Overdue` text of §17 in rows are unchanged. |

The count uses the rule of §17 on the stored data (completion and due date of every todo), not on the rows' markup. The
text is `N overdue` for every N of at least 1 (`1 overdue`, `2 overdue`): no singular or plural form changes it. A
browser whose clock is wrong counts for its own wrong day.

## Function contracts

```ts
// src/lib/overdue-count.ts (§23): pure; no Prisma, no server-only, so a client component may import it
export function countOverdue(
  todos: readonly { readonly completed: boolean; readonly dueDate?: string }[],
  today: string,
): number; // the number of entries for which isOverdue(todo.dueDate, today, todo.completed) (§17); 0 for []; does not modify its input
export function overdueLabel(count: number): string | undefined; // undefined when count === 0, otherwise `${count} overdue`
// src/components/overdue-count.tsx (§23): 'use client'
export function OverdueCount({
  todos,
}: {
  readonly todos: readonly { readonly completed: boolean; readonly dueDate?: string }[];
}): ReactNode; // state `today` starts undefined and is set once to todayOf(new Date()) after mount (§17); renders nothing while today is undefined or overdueLabel(countOverdue(todos, today)) is undefined, otherwise one <span> whose text is that label
// src/app/page.tsx: renders <OverdueCount todos={todos.map(({ completed, dueDate }) => ({ completed, dueDate }))} /> right after <RemainingCount …/>, outside the <ul>, in both states, from the same listTodos() result (no second query)
```

## Out of scope

A timer or focus listener that re-evaluates at midnight, the server's or a stored time zone, a link or button that
filters to the overdue todos, a count of days late, a due-today or due-soon count, highlighting, sorting, grouping or
searching by overdue, a singular or plural wording, a visible `0 overdue`, announcing changes to assistive technology,
a browser clock that disagrees with the real day, and any change to what is stored.
