# §39 Todos: the new-todo counter warns near the limit

Tier: full

- [ ] Lead approves spec

## Intent

A person typing a long title into the "New todo" box is told, in words and in colour, when they have used 180 of the
200 characters a title may have, before the box refuses the next character. The counter of §18 keeps its own text; the
warning is a separate, quiet message that exists only while it applies, and nothing is announced to assistive
technology as it appears or disappears.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-39.1 | State-driven      | WHILE the `<used>` of the §18 counter (`titleCharacterCount` of the box's value) is 180 or more, including a value above 200 that a script set, THE SYSTEM SHALL show inside the `<form>` of the "New todo" box one element `<p id="new-todo-warning">` whose text is exactly `Almost at the character limit`.                                                                                                                                            |
| REQ-39.2 | Unwanted behavior | IF `<used>` is 179 or less THEN THE SYSTEM SHALL NOT render the element: it is absent from the document (no `hidden` attribute, no `display: none`, no empty element), in the HTML the server renders before any script runs as well.                                                                                                                                                                                                                     |
| REQ-39.3 | Ubiquitous        | THE SYSTEM SHALL render the warning with the `class` attribute `text-sm text-amber-700 dark:text-amber-400` (the warning style: amber, where the counter is `text-zinc-500` and the §5 error `text-red-600`), as a sibling placed directly after the counter `<p id="new-todo-count">` and before the §5 error message, inside the same `<form>`.                                                                                                         |
| REQ-39.4 | Event-driven      | WHEN the box's value changes (§18 REQ-18.4), a save ends and the form resets the box (REQ-18.6, REQ-18.7) or Escape empties it (§29) THE SYSTEM SHALL show or remove the warning by the time that event has been handled, from the same value the counter reads: one draft, no second copy of the value.                                                                                                                                                  |
| REQ-39.5 | Ubiquitous        | THE SYSTEM SHALL leave the counter exactly as §18 specifies: its text `<used> / 200`, its id `new-todo-count`, and the box's `aria-describedby`, which is `new-todo-error new-todo-count` while the §5 or §10 error is shown and `new-todo-count` otherwise, at every count including 180 to 200 and above; the warning's id is never listed in it. The warning text matches no `^\d+ / 200$`, so the form still holds exactly 1 element whose text does. |
| REQ-39.6 | Ubiquitous        | THE SYSTEM SHALL NOT make the warning a live region or announce it: no `role` (neither `alert` nor `status`), no `aria-live`, no `aria-atomic`, no `aria-hidden`, and it is not part of the box's accessible description; REQ-18.8 holds, and the form still holds at most the one `role="alert"` message of §5 and §10.                                                                                                                                  |
| REQ-39.7 | Ubiquitous        | THE SYSTEM SHALL define the threshold once in `src/lib/title-count.ts`, next to the limit it derives from (`TITLE_MAX_LENGTH`, §5): the constant `TITLE_WARNING_THRESHOLD` equal to 180 and the predicate `isTitleNearLimit(value)`, true exactly when `titleCharacterCount(value) >= TITLE_WARNING_THRESHOLD`; the component shows the warning on the predicate and holds no other 180.                                                                  |
| REQ-39.8 | Ubiquitous        | THE SYSTEM SHALL leave unchanged what the box accepts (`maxlength` 200), its accessible name "New todo", the field name `title`, the data submitted (only `title`), the §5 and §10 messages and Escape (§29); the warning has no `name`, is not a form control and is never submitted.                                                                                                                                                                    |

The warning judges the same value as the counter (REQ-18.2: trimmed, UTF-16 code units), so 5 spaces and 175
characters read `175 / 200` and show no warning, and one space, 180 characters and one space read `180 / 200` and show
it. At exactly 200, and above, it stays shown. It does not follow the §5 verdict: it warns about the limit, it does
not report an error.

Edits to other sections that this one makes (D-37):

- §18's Out of scope lifts only "a warning colour, a threshold". "A live region" and "any text announced at a
  threshold" stay out, and REQ-18.1, REQ-18.8, AC-18.7 and the `aria-describedby` values in §18's contract hold.
- §29 REQ-29.7 limits §29's own change (Escape in the box) and does not apply to §39: the form gains the warning
  element, and Escape, by emptying the box, removes it with the rest. §29's contract line "signature and markup
  unchanged" limits the same change and does not apply to §39 either.

## Function contracts

```ts
// src/lib/title-count.ts (pure: no Prisma, no server-only; importable from a client component)
// Next to titleCharacterCount and titleCounterText (§18); the limit 200 stays TITLE_MAX_LENGTH (§5).
export const TITLE_WARNING_THRESHOLD = 180;
export function isTitleNearLimit(value: string): boolean; // titleCharacterCount(value) >= TITLE_WARNING_THRESHOLD; never throws
// src/components/todo-form.tsx: TodoForm(): ReactNode, signature unchanged. After <p id="new-todo-count"> and before
// the §5 error <p>, renders {isTitleNearLimit(draft) && <p id="new-todo-warning" className="text-sm text-amber-700
// dark:text-amber-400">Almost at the character limit</p>} (nothing, not a hidden element, otherwise), using the same
// `draft` the counter reads. No role, no aria-live, no name. The box's aria-describedby is unchanged.
```

No Server Action, Zod schema, Prisma model, query or environment variable is added or changes, and the files of §5, §18
and §29 other than `src/components/todo-form.tsx` and `src/lib/title-count.ts` do not change.

## Out of scope

A live region, any text announced at a threshold (assistive technology reads the warning only when it reads the form),
a "characters left" figure or a countdown, a second threshold, a warning that changes the counter's text, colour or
id, listing the warning in `aria-describedby`, blocking the save, a warning on the edit box (§6), the search box (§16)
or the due-date input (§15), a different text per locale.
