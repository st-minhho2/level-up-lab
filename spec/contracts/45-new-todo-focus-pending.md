# §47 Todos: a focus move during a pending add is kept

Tier: full

- [ ] Lead approves spec

## Intent

A person who clicks "Add" may not wait for the save: they press `/` and start a search, open a row's title editor or
tick a box while the save is pending. Today the box takes focus when the save settles, wherever the person already
is, so the text they were typing splits between two fields. After this section a person who has put focus on another
control during the pending save keeps it there, and nothing they type is split. A person who has not moved (focus on
the box, on "Add" or on no control) gets the box focused, as §44 says. Nothing else about adding changes.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-47.1 | Event-driven      | WHEN `createTodoAction` resolves `{ ok: true, … }` for the form of §7 AND, in the commit that settles the result, `document.activeElement` is the "New todo" box, the "Add" button, `document.body` or `null` THE SYSTEM SHALL focus the box as §44 REQ-44.1 says.                                                                                                                                            |
| REQ-47.2 | Unwanted behavior | IF `createTodoAction` resolves `{ ok: true, … }` AND, in the commit that settles the result, `document.activeElement` is any other element (the search box, a title editor, a due-date field, a checkbox, a link, a button other than "Add") THEN THE SYSTEM SHALL NOT call `focus()` on the box: `document.activeElement` and the value of that element are what they were before the result settled.        |
| REQ-47.3 | Ubiquitous        | THE SYSTEM SHALL read `document.activeElement` once for each settled result, at the commit that settles it and not when the form is submitted: a move made and undone during the pending save counts as no move, and a result that kept focus where it was does not change how the next result is judged (§44 REQ-44.4).                                                                                      |
| REQ-47.4 | Ubiquitous        | THE SYSTEM SHALL change nothing but the condition of §44 REQ-44.1: the box's value after a result, the counter (§18), the warning (§39), the `role="alert"` message of §5 and §10, the data submitted, the request count and §44 REQ-44.2, REQ-44.3 and REQ-44.5 are those of §5, §7, §10, §18, §39 and §44; text typed in another field during the pending save stays in that field, and the box holds `''`. |

Edits to other sections that this one makes: §44 REQ-44.1, REQ-44.4 and its contract line say "unless §47 keeps a
focus move made during the pending save"; no other line of any contract changes, and no requirement or criterion is
lifted.

The "`todo-form.tsx` unchanged" notes of the sections named in §44 do not apply to §47, for the same reason as there:
the component is `src/components/todo-form.tsx`. The `TodoForm` signature does not change (`16-title-counter.md:51`
stays true).

## Function contracts

```ts
// src/components/todo-form.tsx (§5, §7, §10, §18, §29, §39, §44, extended; already 'use client'; no new component, props unchanged)
export function TodoForm(): ReactNode; // as before, plus: the focus() of §44 on a successful result is made only if document.activeElement, read in the same layout effect and so in the commit that settles the action, is the box (the existing `box` ref), the "Add" button, document.body or null; otherwise focus() is not called
```

The only file of `src/` this section changes is `src/components/todo-form.tsx`. No new export, Server Action, Zod
schema, Prisma model, query, environment variable, prop or lib function. `src/app/page.tsx`, `src/actions/todos.ts`,
`src/lib/*` and every other component keep their contracts.

How the criteria observe it: AC-47.1 to AC-47.4 are component tests with Testing Library in
`src/components/todo-form-focus-pending.test.tsx` (`createTodoAction` mocked with `vi.hoisted` at `@/actions/todos`,
as `todo-form-focus.test.tsx` does, but returning a deferred promise the test resolves after it moved focus; the
other controls are plain elements rendered beside `<TodoForm>`, so no other component is imported). AC-47.5 and
AC-47.6 are Playwright tests in `e2e/47-new-todo-focus-pending.spec.ts` that hold back the Server Action POST with
`page.route` and `route.continue()` after a 2000 ms wait, and read focus with `toBeFocused`. The sections are numbered
by feature order and the contract files by file order, so §47 lives in `45-new-todo-focus-pending.md`.

## Out of scope

Moving focus back to the box after the person left it; focusing any control other than the box; a save that fails
(§44 REQ-44.3 holds: no focus move); what the other control does with the typed text; a save settling while the tab
or window is in the background; a focus held inside an iframe or a shadow tree; preventing the person from typing
while a save is pending; announcing the decision to assistive technology; every item of §44's Out of scope.
