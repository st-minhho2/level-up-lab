# §18 Todos: a character counter on the new-todo box

Tier: full

- [x] Lead approves spec (lead, 2026-11-01, plan gate of B3.2; D-22)

## Intent

A person typing the title of a new todo sees, under the box, how many of the 200 characters a title may have they have
used, so a long title never ends in a surprise. The number is the one the save will judge, it is right at every moment
the box holds text, and it never changes what is typed, sent or stored.

## Requirements (EARS)

| ID       | Pattern      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-18.1 | Ubiquitous   | THE SYSTEM SHALL show on `/`, inside the `<form>` of the "New todo" text box and after the row that holds the box and the "Add" button, one counter whose text is `<used> / 200`, where 200 is the title limit of §5 (`TITLE_MAX_LENGTH`, one definition) and `<used>` is a whole number written without grouping.                                                                                                                                  |
| REQ-18.2 | Ubiquitous   | THE SYSTEM SHALL compute `<used>` as the length of the box's current value after removing the leading and trailing whitespace that `String.prototype.trim` removes, in UTF-16 code units, which is how §5 judges a title and how the box's `maxlength` counts: a character outside the Basic Multilingual Plane counts 2, a combining mark counts 1, whitespace between other characters counts 1, no normalization and no grapheme grouping apply. |
| REQ-18.3 | State-driven | WHILE the box holds no character, or only whitespace, THE SYSTEM SHALL show `0 / 200`, including in the HTML the server renders before any script runs.                                                                                                                                                                                                                                                                                             |
| REQ-18.4 | Event-driven | WHEN the value of the box changes by typing, pasting, cutting or deleting THE SYSTEM SHALL show the count of the new value by the time that input event has been handled, without a submit.                                                                                                                                                                                                                                                         |
| REQ-18.5 | Ubiquitous   | THE SYSTEM SHALL show the count as it is, never clamped, rounded or hidden: exactly 200 shows `200 / 200`, and a value above 200 (reachable only by setting the box's value from a script, because `maxlength` 200 refuses typing past 200 raw code units) shows its real count, for example `201 / 200`.                                                                                                                                           |
| REQ-18.6 | Event-driven | WHEN a save has finished and the form has reset the box (emptied after a success, emptied after a `title` error of §5, or refilled with the typed title after a `form` failure of §10) THE SYSTEM SHALL show the count of the value the box holds after the reset, even when no input event preceded the reset.                                                                                                                                     |
| REQ-18.7 | State-driven | WHILE a save is pending THE SYSTEM SHALL keep updating the counter for text typed into the box, and when the save ends THE SYSTEM SHALL apply REQ-18.6.                                                                                                                                                                                                                                                                                             |
| REQ-18.8 | Ubiquitous   | THE SYSTEM SHALL expose the counter as part of the box's accessible description (`aria-describedby` of the box lists the counter's id, after the id of the error message when that message is shown) and SHALL NOT make the counter a live region (no `role` `alert` or `status`, no `aria-live`), so that a count changing at each key press is not announced.                                                                                     |
| REQ-18.9 | Ubiquitous   | THE SYSTEM SHALL leave unchanged what the box accepts (`maxlength` 200), its accessible name "New todo", the field name `title`, the data submitted, the §5 and §10 messages and their single `role="alert"` message; the counter is not a form control and is never submitted.                                                                                                                                                                     |

The counter reports the judgement §5 will make, not the box's capacity: the box refuses a character once its raw value
holds 200 code units, so a value padded with spaces can read below `200 / 200` while the box is full, and a value
longer than 200 raw code units can only appear from a script. The counter belongs to the new-todo box only; the edit
box (§6), the search box (§16) and the due-date input (§15) have none.

## Function contracts

```ts
// src/lib/title-count.ts (pure: no Prisma, no server-only; importable from a client component)
// Imports TITLE_MAX_LENGTH from '@/lib/todo-schema' (§5); no second definition of 200.
export function titleCharacterCount(value: string): number; // value.trim().length: UTF-16 code units, as the §5 schema (`z.string().trim()`) counts; never clamps, never throws
export function titleCounterText(value: string): string; // `${titleCharacterCount(value)} / ${TITLE_MAX_LENGTH}`, e.g. '8 / 200'
// src/components/todo-form.tsx: TodoForm(): ReactNode, signature unchanged. Renders <p id="new-todo-count"> (no role,
// no aria-live) with titleCounterText(<the box's value>) after the row that holds the box and the button, inside the
// <form>. The box's aria-describedby is 'new-todo-error new-todo-count' while the error message is shown, else
// 'new-todo-count'. The counter text is derived from the box itself, read after every input event and after every
// form reset; a copy of the value kept in state that the reset does not also reset is the defect REQ-18.6 and
// REQ-18.7 exclude. The counter has no `name` and is not a form control. The Server Action, the Zod schema, the
// error text, maxLength={200}, the label and the button are unchanged.
```

## Out of scope

Counting user-perceived characters (grapheme clusters), Unicode normalization or case folding, a "characters left"
figure or a countdown, a warning colour, a threshold (for example "80 % used") or any text announced at a threshold,
a live region, truncating or rejecting text beyond the limit (the box's `maxlength` and the §5 error do that), a
counter on the edit box (§6), the search box (§16) or the due-date input (§15), a value that reaches the box without
an input event and without a submit (typed before the page is interactive, restored by the browser, set by an
extension) until the next input event or form reset, a change to the schema, the actions or the messages of §5 and
§10, the content of the box after a `title` error (§5, unchanged).
