# §7 Pages, components, the Server Action boundary, health

- `src/app/page.tsx` is a Server Component (`dynamic = 'force-dynamic'`): reads with `listTodos()`, renders
  `<h1>Todos</h1>`, `<TodoForm />`, then either "No todos yet" or a `<ul>` of `<TodoItem>`.
- Mutations happen only through Server Actions in `src/actions/*.ts` (`'use server'`): parse with Zod, call one
  `src/lib` function, `revalidatePath('/')`, return `ActionResult<T>`. Actions return errors as data, never throw
  them to the client.
- Client components (`'use client'`) exist only for state and events: `TodoForm` (`useActionState(createTodoAction)`,
  text box labelled "New todo", button "Add", error under the box), `TodoItem` (checkbox named by the title,
  `toggleTodoAction` in a transition, inline error).
- `src/lib/prisma.ts` is the only Prisma client and imports `server-only`; a client import fails `next build`.
- `GET /api/health` (`src/app/api/health/route.ts`) returns `{ status: 'ok', uptimeSeconds }` with
  `uptimeSeconds = max(0, floor(process.uptime()))`. Route Handlers are read-only.

## Acceptance criteria

| ID     | Then                                                                                                                          |
| ------ | ----------------------------------------------------------------------------------------------------------------------------- |
| AC-7.1 | `GET /api/health` → 200, JSON, `status === 'ok'`, `uptimeSeconds` a non-negative integer                                      |
| AC-7.2 | `healthReport(12.7)` → `{ status: 'ok', uptimeSeconds: 12 }`; `healthReport(-3)` → `uptimeSeconds: 0`; exactly those two keys |
