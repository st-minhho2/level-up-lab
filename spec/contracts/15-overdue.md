# §17 Todos: mark overdue

Tier: full

- [x] Lead approves spec (lead, 2026-11-01)

## Intent

A person who has written a due day on an item (§15) sees at a glance that the day has passed while the item is still
open. An item that is done never nags, an item due today is not late yet, and an item without a day looks as it did
before. "Today" is the day on the person's own calendar, not the server's. The mark is a note on the item: it never
changes which item is shown where, or whether it is done.

## Requirements (EARS)

| ID       | Pattern      | Requirement                                                                                                                                                                                                                                                                                                                                                                |
| -------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-17.1 | Ubiquitous   | THE SYSTEM SHALL take "today" as the calendar day (year, month, day, written `YYYY-MM-DD` with a four-digit year) of the browser's clock in the browser's own time zone; the server's clock, the server's time zone and UTC are never used to decide it.                                                                                                                   |
| REQ-17.2 | State-driven | WHILE a todo is not completed and its due date (§15) is strictly before today THE SYSTEM SHALL show the text `Overdue` in that todo's row, in the due-date element of §15, after the text `Due <date>`.                                                                                                                                                                    |
| REQ-17.3 | State-driven | WHILE a todo has no due date, or a due date that is today or later, THE SYSTEM SHALL show no `Overdue` text in its row.                                                                                                                                                                                                                                                    |
| REQ-17.4 | State-driven | WHILE a todo is completed THE SYSTEM SHALL show no `Overdue` text in its row, whatever its due date; WHEN the todo is marked not completed again THE SYSTEM SHALL evaluate REQ-17.2 for it, and WHEN it is marked completed THE SYSTEM SHALL remove the text, with no page reload in either case.                                                                          |
| REQ-17.5 | Ubiquitous   | THE SYSTEM SHALL render the same markup on the server and in the browser's first render, with no `Overdue` text in it, and add the text only after hydration, so that no hydration mismatch occurs and the server's output does not depend on the date.                                                                                                                    |
| REQ-17.6 | Event-driven | WHEN the row renders again (its due date changes, its edit mode of §15 opens or closes) THE SYSTEM SHALL evaluate REQ-17.2 to REQ-17.4 again for the date shown; WHILE the "Due date" field is open the row shows no `Due` text and so no `Overdue` text.                                                                                                                  |
| REQ-17.7 | State-driven | WHILE the page stays open across the browser's local midnight THE SYSTEM SHALL keep using the day read when the row's due-date element first rendered in the browser; the marker is evaluated against the new day by a reload or a new render of the element, never by a timer.                                                                                            |
| REQ-17.8 | Ubiquitous   | THE SYSTEM SHALL show the marker as plain text `Overdue` in its own element inside the §15 wrapper, with no role, no `aria-label` and no control, so the row still holds exactly one button named "Edit due date" and no element with role `alert` from it; the `Due <date>` text of §15, the list order (§5), completion and the stored due date are never changed by it. |

Completed is read in the browser from the row itself: the first `input[type="checkbox"]` inside the nearest `li`
ancestor of the §15 wrapper; no such `li` or checkbox counts as not completed. The comparison is on the two
`YYYY-MM-DD` strings, which order as calendar days because both are fixed width. The marker is text, not colour alone.
A browser whose clock is wrong shows the marker for its own wrong day.

## Function contracts

```ts
// src/lib/todo-overdue.ts (§17): pure; no Prisma, no server-only, so a client component may import it
export const OVERDUE_LABEL: 'Overdue';
export function todayOf(now: Date): string; // local calendar day of `now`: `${String(now.getFullYear()).padStart(4, '0')}-${MM}-${DD}` from getMonth() + 1 and getDate(), each padded to 2; never UTC, never Intl
export function isOverdue(dueDate: string | undefined, today: string, completed: boolean): boolean; // !completed && dueDate !== undefined && dueDate < today (string comparison of two YYYY-MM-DD values)
// src/components/todo-due-date.tsx (§15, extended; no new component, props unchanged)
export function TodoDueDate({
  todoId,
  dueDate,
}: {
  readonly todoId: string;
  readonly dueDate: string | undefined;
}): ReactNode; // as §15, plus: state `today` starts undefined (so the server render and the first client render show no marker) and is set once to todayOf(new Date()) after mount; after mount and after every render the checkbox of the nearest `li` (REQ-17.4 rule) is read; while not editing, a <span> with OVERDUE_LABEL follows the `Due <date>` span exactly when today is set and isOverdue(dueDate, today, completed)
```

No file other than `src/lib/todo-overdue.ts` and `src/components/todo-due-date.tsx` changes in `src/`: the row component
(`src/components/todo-item.tsx`), `src/lib/todos.ts`, the actions, the page and the logger keep their contracts.

## Out of scope

A timer or focus listener that re-evaluates at midnight, the server's or a stored time zone, a due-soon highlight or
any count of days late, sorting, grouping, filtering or searching by overdue, a different marker for a todo that was
done late, a visible change to completed rows, a locale-formatted date (§15), a browser clock that disagrees with
the real day, a notification, a new control, and any change to what is stored.
