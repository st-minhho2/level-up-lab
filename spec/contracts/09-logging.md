# §11 Logging failures

## Intent

When a save fails and the person is told `Could not save, try again`, whoever runs the application can find out
afterwards which action failed and why. The person who clicked sees exactly what they saw before. A todo that no
longer exists, a title that is not valid and a save that worked leave nothing behind. What the person typed and the
database credentials are never written down.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| REQ-11.1 | Event-driven      | WHEN creating a todo, toggling a todo, saving an edited title or clearing completed todos resolves to the `form` failure of §10 because a value was thrown THE SYSTEM SHALL write exactly one log entry for that failure, before the result is returned.                                                                                                                                                                                                                                                                                                                                                                             |
| REQ-11.2 | Ubiquitous        | THE SYSTEM SHALL write each log entry as one line of JSON, terminated by `\n`, on the standard error stream and never on the standard output stream, with the fields `level`, `time`, `msg`, `action` and `error`, in that order.                                                                                                                                                                                                                                                                                                                                                                                                    |
| REQ-11.3 | Event-driven      | WHEN the thrown value is an `Error` THE SYSTEM SHALL record its `name`, its `message`, as `code` its own `code` if that is a string or else its `errorCode` if that is a string (no `code` when neither is), and its `stack`; WHEN it is any other value THE SYSTEM SHALL record the name `NonError` and its text as the message, with no `code` and no `stack`.                                                                                                                                                                                                                                                                     |
| REQ-11.4 | Unwanted behavior | IF the recorded `message` or `stack` contains a secret of `DATABASE_URL` (the whole value; its password as the URL parser returns it, percent-decoded, and percent-decoded then percent-encoded again; the value of each `password` and `sslpassword` query parameter as written and percent-decoded) THEN THE SYSTEM SHALL replace each occurrence with `[redacted]`, longer secrets before shorter ones, before the entry is cut to 500 characters (`message`) and 2000 characters (`stack`); an empty string is never a secret, and a form that cannot be percent-decoded is left out while every other secret is still replaced. |
| REQ-11.5 | Event-driven      | WHEN an action succeeds, finds no todo for its id (§5, §6) or rejects its input as invalid (§5, §6) THE SYSTEM SHALL write no log entry.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| REQ-11.6 | Unwanted behavior | IF writing the entry fails, or the database URL cannot be read from the validated environment (§4), THEN THE SYSTEM SHALL still return the §10 result without throwing; an unreadable URL means no redaction is applied.                                                                                                                                                                                                                                                                                                                                                                                                             |
| REQ-11.7 | Ubiquitous        | THE SYSTEM SHALL return to the person the §10 result and nothing from the log entry: no error name, message, stack or code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

The entry carries the action's name and the thrown value only. The typed title, the submitted form data and the todo
id are never fields of an entry. The host and user name of the database may appear inside `message` when the database
driver puts them there; only the full `DATABASE_URL` value, its password and its `password` and `sslpassword` query
parameters, in the forms REQ-11.4 names, are treated as secrets.

## Function contracts

```ts
// src/lib/logger.ts (§11): no `server-only` and no Prisma import; reads configuration only through getEnv() (§4).
export type MutationActionName =
  'createTodoAction' | 'toggleTodoAction' | 'updateTodoTitleAction' | 'clearCompletedTodosAction';
export function logMutationFailure(action: MutationActionName, error: unknown): void;
// Synchronous. Writes exactly one chunk, JSON.stringify({ level: 'error', time: new Date().toISOString(),
// msg: 'mutation failed', action, error: { name, message, code?, stack? } }) + '\n', with process.stderr.write; never
// process.stdout and never `console`. Module-level constants (not exported): LOG_MESSAGE_MAX_LENGTH = 500,
// LOG_STACK_MAX_LENGTH = 2000, REDACTED = '[redacted]'. Redaction: from value = getEnv().DATABASE_URL and
// url = new URL(value) the secrets are value; url.password, decodeURIComponent(url.password) and
// encodeURIComponent(decodeURIComponent(url.password)); and, for every `&`-separated pair of url.search without its
// leading `?` whose name (the text before the pair's first `=`) is exactly `password` or `sslpassword`, its raw value
// (the text after that `=`) and decodeURIComponent(raw value). A form whose decodeURIComponent throws is left out and
// the other secrets stay; an empty string is never a secret; a pair without `=` gives none. Each occurrence of each
// secret in message and stack is replaced with REDACTED, secrets ordered by length, longest first, then the text is cut
// to the two lengths. For an Error: name = error.name, message, `code` = error.code when typeof error.code
// is 'string', otherwise error.errorCode when typeof error.errorCode is 'string' (Prisma's initialization errors carry
// their code there), otherwise no `code` key; no other property of the Error is read and no `errorCode` key is written;
// `stack` only when typeof error.stack is 'string'. For anything else: name 'NonError', message = String(value).
// The whole body runs in one try/catch: any failure (getEnv throws, the write throws) returns undefined; when getEnv
// throws the entry is still written, unredacted. There is no level switch, no environment key and no NODE_ENV branch:
// the same line is written in development, test and production.
// src/actions/todos.ts ('use server'), signatures unchanged. In each catch arm, after the TodoNotFoundError arm of
// toggle and edit and before the return, call logMutationFailure('<the action's own name>', error); createTodoAction and
// clearCompletedTodosAction bind the caught value as `error`. The Zod parse stays outside the try (no entry for a title
// error), the TodoNotFoundError arm returns before the call (no entry), and the success path never calls it.
// How tests observe it: action tests mock '@/lib/logger' at the module boundary (vi.hoisted object with one
// logMutationFailure spy, like the lib mocks) and assert on mock.calls[0]; src/lib/logger.test.ts mocks '@/lib/env'
// (getEnv), uses vi.useFakeTimers() with vi.setSystemTime, and spies on process.stderr.write and process.stdout.write
// (mockReturnValue(true)); no test spies on `console`.
```

## Out of scope

Log levels and a level switch (§4 gains no key), a logging dependency, `console` in `src/`, shipping, rotation or
aggregation of the output, request, session or correlation ids, the todo id or the typed title as fields, entries for
expected failures (a missing todo, an invalid title) or for successes, failures of the page's reads (§5) or of the
request itself (§10), a human-readable format for development, a stack for a value that is not an `Error`, an error
page (`error.tsx`), alerting, a separate `errorCode` field or any field naming the property the code came from, any other
property of the thrown value (`meta`, `clientVersion`, `retryable`, `cause`), a `code` for a value that is not an `Error`,
redaction of `name` or `code`, any query parameter other than `password` and `sslpassword` (`user`, `sslcert`,
`sslkey`, `sslidentity`, `host`), a parameter name in another case or percent-encoded, `+` read as a space, decoding
more than once, a fragment or prefix of a secret, secrets from any other environment key.
