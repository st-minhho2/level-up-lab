# §48 Todos: Escape from the title editor returns focus to its button

Tier: full

- [ ] Lead approves spec

## Intent

A person who presses Escape in an item's title editor leaves the edit and expects to carry on from the same place with
the keyboard. Today the field disappears and nothing is focused, so the next key goes to the page and the person has to
find the row again. After this section the row's "Edit title" button takes focus, so Enter reopens the editor, Tab
moves on from that row and `/` still goes to the search box. A save, successful or not, moves no focus: the person may
have gone elsewhere while it was pending and keeps that place. Nothing else about editing changes.

## Requirements (EARS)

| ID       | Pattern           | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-48.1 | Event-driven      | WHEN Escape leaves edit mode (§24 REQ-24.1: the key is pressed in the title field and no action of that row is in flight) THE SYSTEM SHALL make the row's "Edit title" button `document.activeElement`, in the commit that shows the row in view mode, once for that Escape.                                                                                                                                                                                                                                                                                |
| REQ-48.2 | State-driven      | WHILE an action of that row is in flight (a save, §6; or a toggle, §10: the cases in which "Edit title" is disabled) THE SYSTEM SHALL ignore Escape as §24 REQ-24.5 says, and move no focus: the row stays in edit mode and `document.activeElement` is what it was.                                                                                                                                                                                                                                                                                        |
| REQ-48.3 | Unwanted behavior | IF a row leaves edit mode by a successful save (§6 REQ-6.2), or stays in it after a rejected save (§6 REQ-6.4 to REQ-6.6) or a failed save (§10 REQ-10.3), THEN THE SYSTEM SHALL NOT focus a control: no "Edit title" button, no field, no other element receives `focus()`; a control the person focused while the save was pending stays `document.activeElement`, and when the removed field was the focused element `document.activeElement` is `document.body`, as the browser leaves it.                                                              |
| REQ-48.4 | Ubiquitous        | THE SYSTEM SHALL move focus to the button only for the Escape of REQ-48.1: a later re-render of the row (a new `todo` prop, a message shown or removed, a save or toggle pending or settled), a later switch into edit mode (§41) and a later successful save never focus the button, so a person who left the row after the Escape, or who saved later, is not pulled back.                                                                                                                                                                                |
| REQ-48.5 | Ubiquitous        | THE SYSTEM SHALL change nothing but that focus: the draft discarded, the stored title shown, the message removed and the request count (none) of §24 REQ-24.1 to REQ-24.4, the Enter, ArrowLeft and other keys of REQ-24.6, the focus and selection on entering edit mode again (§41 REQ-41.1, REQ-41.2) and the button's name, attributes and place among the row's controls (§6, AC-35.3) are as before; the button is not a text-entry element, so `/` pressed on it moves focus to "Search todos" and cancels the key as §25 REQ-25.1 and REQ-25.3 say. |

## Function contracts

```ts
// src/components/todo-item.tsx (§7, §6, §24, §41, §19, §20, §10, extended; no new component, props unchanged)
export function TodoItem({ todo }: { readonly todo: Todo }): ReactNode; // as before, plus: when the title field's keydown for Escape leaves edit mode (not ignored while a save or toggle of the row is pending), after the "Edit title" button is in the document it receives focus(), once for that Escape; a save result, a re-render, a changed todo prop and a later switch into edit mode do not call focus() on the button
```

The only file of `src/` this section changes is `src/components/todo-item.tsx`. No new export, Server Action, Zod
schema, Prisma model, query, environment variable, prop or lib function. `src/app/page.tsx`,
`src/actions/todos.ts`, `src/components/todo-due-date.tsx`, `src/components/delete-todo-button.tsx` and `src/lib/*`
keep their contracts. The button's attributes (`aria-label`, `title`, `type`, `disabled`) do not change.

How the criteria observe it: AC-48.1 to AC-48.6 are component tests with Testing Library in
`src/components/todo-item-escape-focus.test.tsx` (`updateTodoTitleAction` and `toggleTodoAction` mocked with
`vi.hoisted` at `@/actions/todos`; the "Search todos" input is a plain element rendered beside `<TodoItem>`; promises
resolved by hand; the `focus` spy is `vi.spyOn(HTMLElement.prototype, 'focus')` with the receiver read from
`mock.contexts`). AC-48.7 is a Playwright test in `e2e/48-escape-title-focus.spec.ts` that reads
`document.activeElement` with `page.evaluate` and counts POSTs to `/`. The sections are numbered by feature order and
the contract files by file order, so §48 lives in `46-escape-title-focus.md`.

## Out of scope

Focus after a successful or failed save (REQ-48.3: none moves), restoring focus after Cancel by blur (§6), a visible
focus style of our own, scrolling the row into view, Escape in other fields (due date §15, new-todo box §29, search
box §27), Escape while no field is open, focus after the delete button (§19) or the due-date editor (§15), the
selection of the title on the next edit (§41), announcing the focus move to assistive technology.
