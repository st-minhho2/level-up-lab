# §31 Todos: say "Due today" on an open todo due today

Tier: full

- [ ] Lead approves spec

## Intent

A person who has written a due day on an item (§15) sees at a glance that the day is today while the item is still
open. An item that is done never shows it, an item due on another day or without a day looks as it did before. "Today"
is the day on the person's own calendar, the same day §17 uses. The mark is a note on the item: it never changes which
item is shown where, or whether it is done.

## Requirements (EARS)

| ID       | Pattern      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-31.1 | State-driven | WHILE a todo is not completed and its due date (§15) equals today (§17 REQ-17.1, the browser's calendar day) THE SYSTEM SHALL show the text `Due today` in that todo's row, in the due-date element of §15, after the text `Due <date>`.                                                                                                                                                                                                                                                                 |
| REQ-31.2 | State-driven | WHILE a todo has no due date, or a due date that is not today, THE SYSTEM SHALL show no `Due today` text in its row.                                                                                                                                                                                                                                                                                                                                                                                     |
| REQ-31.3 | State-driven | WHILE a todo is completed THE SYSTEM SHALL show no `Due today` text in its row, whatever its due date; WHEN the todo is marked not completed again THE SYSTEM SHALL evaluate REQ-31.1 for it, and WHEN it is marked completed THE SYSTEM SHALL remove the text, with no page reload in either case (§17 REQ-17.4 rule for reading completed).                                                                                                                                                            |
| REQ-31.4 | Ubiquitous   | THE SYSTEM SHALL render the same markup on the server and in the browser's first render, with no `Due today` text in it, and add the text only after hydration, so that no hydration mismatch occurs and the server's output does not depend on the date.                                                                                                                                                                                                                                                |
| REQ-31.5 | Event-driven | WHEN the row renders again (its due date changes, its edit mode of §15 opens or closes) THE SYSTEM SHALL evaluate REQ-31.1 to REQ-31.3 again for the date shown; WHILE the "Due date" field is open the row shows no `Due` text and so no `Due today` text.                                                                                                                                                                                                                                              |
| REQ-31.6 | State-driven | WHILE the page stays open across the browser's local midnight THE SYSTEM SHALL keep using the day read when the row's due-date element first rendered in the browser (§17 REQ-17.7); the marker is evaluated against the new day by a reload or a new render of the element, never by a timer.                                                                                                                                                                                                           |
| REQ-31.7 | Ubiquitous   | THE SYSTEM SHALL show the marker as plain text `Due today` in its own element inside the §15 wrapper, with no role, no `aria-label` and no control, so the row still holds exactly one button named "Edit due date" and no element with role `alert` from it; the `Due <date>` text, the `Overdue` marker of §17 (never shown together with `Due today`, a due date being either strictly before today or equal to it), the list order (§5), completion and the stored due date are never changed by it. |

Completed is read in the browser from the row itself, by the rule of §17 (the first `input[type="checkbox"]` inside
the nearest `li` ancestor of the §15 wrapper; no such `li` or checkbox counts as not completed). The comparison is on
two `YYYY-MM-DD` strings. The marker is text, not colour alone. A browser whose clock is wrong shows the marker for its
own wrong day.

## Function contracts

```ts
// src/lib/todo-due-today.ts (§31): pure; no Prisma, no server-only, so a client component may import it
export const DUE_TODAY_LABEL: 'Due today';
export function isDueToday(dueDate: string | undefined, today: string, completed: boolean): boolean; // !completed && dueDate !== undefined && dueDate === today (two YYYY-MM-DD values)
// src/components/todo-due-date.tsx (§15, §17, extended; no new component, props unchanged)
export function TodoDueDate({
  todoId,
  dueDate,
}: {
  readonly todoId: string;
  readonly dueDate: string | undefined;
}): ReactNode; // as §17, plus: while not editing, a <span> with DUE_TODAY_LABEL follows the `Due <date>` span exactly when today (§17's state, set after mount) is set and isDueToday(dueDate, today, completed)
```

`today` comes from `todayOf` of §17. No file other than `src/lib/todo-due-today.ts` and
`src/components/todo-due-date.tsx` changes in `src/`: `src/lib/todo-overdue.ts`, the row component, `src/lib/todos.ts`,
the actions, the page and the logger keep their contracts.

## Out of scope

A due-soon highlight for any day other than today (tomorrow, this week), a count of days left, a count of todos due
today, a timer or focus listener that re-evaluates at midnight, the server's or a stored time zone, sorting, grouping,
filtering or searching by due today, a different marker for a todo done today, a visible change to completed rows,
announcing the marker to assistive technology, a locale-formatted date (§15), a browser clock that disagrees with the
real day, a notification, a new control, and any change to what is stored.
