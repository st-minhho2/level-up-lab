# L3 — Plan-first: "think before coding"

Goal: no multi-file change starts without a one-screen plan a person approved, and the PR is reviewed against that
plan before it is reviewed line by line.

## Rules

- Multi-file or unclear tasks start in plan mode (read-only). One-sentence diffs skip it and say so.
- A plan names the files, the interfaces touched and how to verify, and fits on one screen; longer means two tasks.
- A person approves before coding. A change of direction means: update the plan, re-approve, then code.
- The plan is the PR body. Reviewers first compare the diff to the plan (checkbox "Diff matches the approved plan"),
  then review the code.

## Checklist

- [x] `.claude/rules/planning.md` (applies to every path) with the trigger, the three plan parts, the one-screen
      limit, approval and re-approval rules, and the reviewer's first job
- [x] `.github/pull_request_template.md` with a mandatory **Plan** section (Files / Interfaces touched /
      Verification, approver + date) and the "Diff matches the approved plan" checkbox first in the checklist
- [x] `CLAUDE.md` session rules point at the planning rule

## How it is used with Claude Code

1. Developer: "FEAT-002: archive completed todos" → agent enters plan mode, reads the spec and the code, writes the
   plan (files, interfaces, verification), exits plan mode.
2. Developer reads the plan on one screen, approves or edits. No code before this.
3. Agent implements. If it needs a file not in the list it stops and asks; the plan is updated and re-approved.
4. The PR body carries the plan. The reviewer ticks "Diff matches the approved plan" only after comparing the
   file list with the diff; a mismatch is sent back before any other comment.

## Watch-outs

- A plan with "and also tidy up X" is two tasks. Scope creep in the plan is scope creep in the diff.
- "Approved" without a name and date in the PR body is not approval; the template has a slot for both.
- Re-approval is cheap when it happens at the moment the direction changes and expensive after the diff is 400
  lines. The rule says stop at the moment.
- Plans must name verification commands with expected numbers; "run the tests" is not verifiable.

## Metrics

| Type    | Metric                               | Target | How collected                                                              |
| ------- | ------------------------------------ | ------ | -------------------------------------------------------------------------- |
| Speed   | Multi-file PRs with an approved plan | 100%   | PRs touching > 1 file whose body has Plan + "approved by" / all such PRs   |
| Quality | PRs needing a second design round    | < 10%  | PRs where the reviewer asked to change the approach (not a line) / all PRs |

## Exit criteria for L3

Three consecutive multi-file PRs merged where the reviewer did not ask "why did you touch this file?".
