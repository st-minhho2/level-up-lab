# L5 — Enforcement: "checks that never forget"

Goal: every convention that matters is enforced by a machine at the earliest possible moment, in four layers,
and the last two (CI, merge policy) do not depend on the agent behaving.

## The four layers

| Layer           | Where                        | Catches                                                                                       | Independent of the agent  |
| --------------- | ---------------------------- | --------------------------------------------------------------------------------------------- | ------------------------- |
| 1. Agent hooks  | `.claude/settings.json`      | destructive commands, secret reads, non-local migrations; formats every edit; reminds to test | no (agent runtime)        |
| 2. Git hooks    | `lefthook.yml`               | formatting, lint, types, secrets, commit subject, before the commit exists                    | partly (human can bypass) |
| 3. CI gate      | `.github/workflows/ci.yml`   | everything above plus unit/e2e/mutation/Semgrep and the guards                                | yes                       |
| 4. Merge policy | `.github/rulesets/main.json` | direct pushes, unreviewed merges, red checks, agent self-merge                                | yes                       |

### 1. Agent hooks (`.claude/hooks/`)

- `guard-bash.sh` (PreToolUse Bash, exit 2 = blocked): `rm -rf` in any flag spelling, `git push --force|-f|+ref|--force-with-lease`,
  `prisma migrate reset` / `db push` / `db execute`, any Prisma migrate/db or inline `DATABASE_URL=` whose host is not
  localhost / 127.0.0.1 / postgres, reads of `.env*` (except `.env.example`), keys and credential stores, printing
  secret-looking variables or the whole environment.
- `guard-read.sh` (PreToolUse Read): same secret files for the Read tool. `permissions.deny` backs it up for the
  common `.env` names.
- `format-after-edit.sh` (PostToolUse Edit|Write|MultiEdit): `prettier --write`, then `eslint --fix` on TS/JS.
- `require-review.sh` (Stop and SubagentStop) + `mark-reviewed.sh` + `review-lib.sh`: the review gate. A change
  under `src/`, `e2e/`, `prisma/` is fingerprinted; a stop with an unrecorded fingerprint is blocked once per
  session with the `/review-loop` instruction; `mark-reviewed.sh` re-runs lint, typecheck and tests, then records
  it. `stop_hook_active` and a per-session marker prevent loops (D-4).
- `path-guard.sh` (PreToolUse Edit|Write in each agent's frontmatter): per-role write scopes as globs with `!`
  denies; resolves `..` and symlinks; a blocked write tells the role to report back.
- `permissions.deny` also blocks hook bypasses (`--no-verify`, `-n`, `core.hooksPath`, `LEFTHOOK=0`) and
  `gh pr merge|review`; `permissions.allow` pre-approves the routine project commands so roles do not prompt.
- All scripts are bash 3.2-safe (regexes live in variables) and parse JSON with node, so they run on macOS and in
  the dev container without jq.

### 2. Git hooks (Lefthook, installed by `pnpm install` through `prepare`)

pre-commit, parallel: `prettier --check` and `eslint` on staged files only, `tsc --noEmit` (whole project, types
cross files), `gitleaks git --pre-commit --staged --redact`. commit-msg: Conventional Commits subject. Budget 30 s.
Bypass `LEFTHOOK=0 git commit` exists for emergencies and is visible in the commit body; CI re-runs everything.

### 3. CI gate (`ci.yml`, `permissions: contents: read`)

Jobs: `lint`, `typecheck`, `test` (Vitest with v8 coverage, uploaded), `e2e` (Playwright against a Postgres
service container, `pnpm build && pnpm start`), `mutation` (Stryker on `src/lib` + `src/actions`, breaks below 70%),
`semgrep` (`p/default`, `p/typescript`, `p/secrets`, `--error`), `guards`:

- `scripts/ci/check-suppressions.sh`: new `eslint-disable` / `@ts-ignore` / `@ts-expect-error` / `@ts-nocheck` lines fail.
- `scripts/ci/check-config-change.sh`: changes to ESLint, Prettier, tsconfig, Lefthook, gitleaks, Vitest, Playwright,
  Stryker, `.github/**`, `scripts/ci/**`, `.claude/settings.json`, `.claude/hooks/**` fail unless the PR carries the
  label `config-change-approved`.
- `scripts/ci/check-feat-commits.sh`: a commit whose subject starts with `feat(` must not touch `*.test.ts(x)` or
  `e2e/**` (L6 commit convention).
- L6 adds `check-ac-coverage.sh` and `verify-red.sh` to this job.

Every job runs in `container: node:24-bookworm`, the same image as `.devcontainer/`.

### 4. Reviewer agent (`review.yml`)

`anthropics/claude-code-action@v1` on `pull_request` (opened, synchronize, ready_for_review), before human review.
Read-only: workflow permission `contents: read`, allowed tools limited to Read/Grep/Glob, `gh pr view|diff|comment`,
`git log|diff` and the inline-comment tool; no Edit, no Write, no push. The prompt allows **blocking findings
only** (spec mismatch, file outside the plan, rule violation, correctness/security bug) and forbids style comments,
refactor suggestions, approvals and change requests. Needs the `ANTHROPIC_API_KEY` repository secret; without it the
job logs a notice and is skipped. It is deliberately **not** a required check.

## Merge policy (`.github/rulesets/main.json`)

Applied with:

```bash
gh api -X POST repos/<owner>/level-up-lab/rulesets --input .github/rulesets/main.json
```

| Rule                                                                                                | Effect                                                    |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `deletion`, `non_fast_forward`, `required_linear_history`                                           | `main` cannot be deleted, force-pushed or merge-committed |
| `pull_request`: 1 approval, dismiss stale, last-push approval, threads resolved, squash/rebase only | no direct push; every change is a reviewed PR             |
| `required_status_checks` strict: `lint typecheck test e2e mutation semgrep guards`                  | red or stale CI blocks merge                              |
| `bypass_actors: []`                                                                                 | nobody, including admins and apps, bypasses               |

**Agents cannot merge** because: (1) the CI token is `contents: read`; (2) the reviewer workflow has no `contents:
write`; (3) a PR author cannot approve their own PR and `require_last_push_approval` means the last pusher needs
someone else's approval; (4) there are no bypass actors; (5) auto-merge is not enabled on the repository.

On a GitHub Free plan the ruleset is only enforced for public repositories; for this private lab the JSON is the
policy of record and is applied the day the repository becomes public or the plan allows it.

### Hotfix lane

For a production incident only:

1. Branch `hotfix/<ticket>` from `main`, PR labelled `hotfix`.
2. Minimal gate: `lint`, `typecheck`, `test` (unit + component) and **one human review**. `e2e`, `mutation`,
   `semgrep` and `guards` are skipped by the label (they report "skipped", which the ruleset accepts).
3. Squash-merge, deploy.
4. Within **one working day**, a follow-up PR without the label restores the full gate: regression test for the
   bug (`test(FEAT-xxx):` commit), spec update if behavior changed, mutation score back above 70%. The follow-up PR
   links the hotfix PR, and a row goes into `docs/mistake-log.md` naming what let the bug through.

## Watch-outs

- Hooks guard the agent, not the human. The human bypass is `LEFTHOOK=0`; the policy that cannot be bypassed is the
  ruleset. That is why layers 3 and 4 exist.
- `check-config-change.sh` also protects the hooks and the CI scripts themselves; otherwise a feature PR could
  remove the guard that would have caught it.
- A skipped required job (hotfix label) counts as passing for the ruleset. The label is therefore a privileged
  action: only maintainers may add it, and the follow-up PR is the audit trail.
- gitleaks allowlists AWS's documented example keys; probe with a generated key, not `AKIAIOSFODNN7EXAMPLE`.
- `lefthook run pre-commit` with nothing staged runs tsc and gitleaks only; the measured time includes them.
- The reviewer agent sees the PR body. A missing Plan section is itself a blocking finding.

## Exit criteria for L5

Five consecutive PRs where CI was green on the first push after local hooks, the reviewer agent posted no
blocking finding a human later confirmed as a miss, and no mechanical comment appeared in human review.
