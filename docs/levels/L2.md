# L2 — Advanced setup: "a controlled environment"

Goal: every developer and every agent session runs in the same environment as CI, with local throwaway
credentials only, so "works on my machine" and "works in CI" are the same statement.

## Rules

- The dev container is built from the exact image string CI uses (`node:24-bookworm`). Changing one without the
  other is a config change that needs the `config-change-approved` label.
- The container mounts the repository root. A git worktree folder is never the workspace: its `.git` is a pointer
  file to the main checkout and breaks outside the mount.
- No production credentials anywhere in the repo, the container, or `.env.example`. SSH keys stay on the host;
  the ssh-agent socket is forwarded instead.
- MCP servers default to none. Adding one follows the four conditions in `.mcp.json` and treats returned data as
  untrusted.
- Mistakes the agent repeats are logged in `docs/mistake-log.md` with the artifact that now prevents them, and the
  log is pruned every sprint.

## Checklist

- [x] `.devcontainer/devcontainer.json` + `.devcontainer/docker-compose.yml` on `node:24-bookworm`, repo root at
      `/workspace`, shared pnpm store volume, `postCreateCommand` runs `scripts/setup-env.sh`
- [x] `docker-compose.yml` with Postgres 17, healthcheck, host port 5433 (`POSTGRES_PORT` override)
- [x] `.env.example` with every key `src/lib/env.ts` validates; `.env*` git-ignored except the example
- [x] `scripts/setup-env.sh`: idempotent `.env` copy, missing-key warning without printing values, install from the
      shared pnpm store (`--prefer-offline`), `prisma generate`
- [x] `.mcp.json` empty with the policy inline
- [x] `docs/mistake-log.md` seeded with the mistakes hit while building L1–L2

## Watch-outs

- The devcontainer feature `docker-outside-of-docker` is needed only for `scripts/worktree-prune.sh` (it drops
  schemas through `docker compose exec`). Remove it if the team never prunes from inside the container.
- `PLAYWRIGHT_BROWSERS_PATH` is set in the container so browsers are not written into the mounted repo.
- `pnpm install --prefer-offline` falls back to the network silently; a cold store in CI still downloads.
- `scripts/setup-env.sh` does not start Postgres; a developer without Docker can still run `pnpm test`.

| Quality | Repeated mistakes already covered by a rule, per sprint | 0      | Rows in `docs/mistake-log.md` whose "Seen" increased while a prevention existed |

## Exit criteria for L2

Clone → `scripts/setup-env.sh` → `docker compose up -d` → green `pnpm test` and `pnpm test:e2e`, with no secret
handed to the developer and the same image as CI.
